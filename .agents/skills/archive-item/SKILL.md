# Навык: архивация завершённого

Переносит завершённое из любой зоны в `archive/`, сохраняя историю. Это **не удаление**: путь,
дата и причина остаются, обратный ход возможен.

## Вход

- Что архивируем: путь к файлу или папке (проект, область, гипотеза, карточка, материал).
- Опционально: причина одной фразой.

## Протокол

### Шаг 1 — Определить объект
Если пользователь назвал вещь словами, а не путём, найди кандидатов и покажи список: путь, тип,
дата последнего изменения. Уточни выбор, если кандидатов больше одного.

### Шаг 2 — Проверить входящие ссылки
Найди `[[wikilink]]` и относительные ссылки на архивируемое в остальных зонах. Если ссылки есть —
**покажи их до переноса** и спроси, архивировать ли: иногда правильный ответ «нет, это ещё живое».
Ссылки не переписывай молча.

### Шаг 3 — Перенести с сохранением пути
`projects/504-team/` → `archive/projects/504-team/`. Структура внутри `archive/` повторяет исходную,
чтобы было видно происхождение. Существующий путь в архиве не перезаписывай — добавь суффикс даты.

### Шаг 4 — Проставить метку
Во frontmatter (или первой строкой, если frontmatter нет):

- `archived: YYYY-MM-DD`
- `archived_reason:` — одной фразой, словами владельца;
- `archived_from:` — исходный путь.

Для папки метка ставится в её README или карточке; каждый файл внутри не размечается.

### Шаг 5 — Показать итог
Что перенесено, откуда, куда, сколько входящих ссылок осталось. Если ссылки остались — назови их
явно: это долг владельца, а не ошибка навыка.

## Границы

- Не архивируй `operation/` — журнал и сессии сами по себе хронология.
- Не архивируй то, что в работе: гипотеза со `status: exploring` живёт в `discovery/`, карточка на
  ревью — в `concepts/`.
- Не удаляй ничего. Навык только переносит.

## Возврат из архива

По просьбе «верни из архива» — перенеси по `archived_from` и сними три поля метки.

## Связи

- `/capture-hypothesis` — вход в `discovery/`; отвергнутая гипотеза уезжает сюда.
- `/review-concepts` — карточки концептов; устаревшая карточка архивируется, а не удаляется.
