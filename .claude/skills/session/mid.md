# Фаза MID — чекпоинт с рулём

Роутер и инварианты — [SKILL.md](SKILL.md).

Чекпоинт — не просто отметка «я тут поработал». Это место, где сессия **сверяется с целью и, если
надо, меняет курс**. Отсюда «с рулём»: лог фиксирует прошлое, чекпоинт управляет будущим.

## MID-1. Решения — в атом сразу

Каждое решение, принятое с прошлого чекпоинта, записывается **сейчас**, а не в конце сессии.
В секцию `## Решения зафиксированы` атома:

```markdown
- ЧЧ:ММ — <решение утвердительной фразой>
  Следствия: <что теперь верно, что перестало быть верным>
```

Решение, отложенное «до итога», теряется: к концу сессии остаётся память о выводе, но не о том,
что именно было решено и почему. Решение утвердительной фразой («храним X рядом с Y»), а не
описанием обсуждения («поговорили про хранение»).

## MID-2. Сверка с целью (goal-check)

Перечитай секцию «Цель» атома и задай себе два вопроса — вслух, с ответом в чат:

1. **Двигает ли сделанное к цели сессии?**
2. **Не сместился ли фокус** — работа идёт над тем, ради чего сессия начиналась?

Это единственное место, где расхождение обнаруживается вовремя. Без сверки сессия узнаёт о
смещении фокуса на закрытии, когда время уже потрачено.

## MID-3. Вердикт курса

Одна строка в `## Хронология` атома, всегда с явным исходом:

| Исход | Когда | Что делаешь |
|---|---|---|
| ✅ **по курсу** | сделанное двигает к цели, фокус на месте | продолжаем |
| 🔄 **корректируем** | фокус сместился или цель оказалась не той | одной строкой: **что меняем**; при необходимости правишь «Цель» с пометкой |
| 🏁 **цель достигнута** | получено то, ради чего начинали | предложи закрыть сессию (`/close-session`) |

```markdown
- **ЧЧ:ММ MID:** <исход-эмодзи> <одна строка резюме>
```

«🔄 корректируем» **обязано** нести содержательную строку «что меняем» — без неё вердикт
превращается в ритуальную галочку.

## MID-4. Ход и артефакты

- В `## Создано / Обновлено` атома — новые файлы и карточки (по строке).
- В `operation/daily/<ГГГГ-ММ-ДД>.md`, под открытым блоком сессии — **одна** строка:

  ```markdown
  - 🟡 ЧЧ:ММ MID: <исход-эмодзи> <одна строка резюме>
  ```

- Frontmatter атома: `Status: "🟡 Продолжение"`, `Active: true` (сессия не закрывается).

В день не копируются полные блоки — только строка со ссылкой; полнота живёт в атоме.

## MID-5. Промпт на продолжение — обязательный выход каждого чекпоинта

Не «когда контекст кончается», а **на каждом** чекпоинте: чат может оборваться в любой момент.

1. Обнови секцию `## 🔁 Команда для продолжения` атома:

   ```markdown
   0. **Сессия:** [[S{ГГГГММДД}T{ЧЧММ}-{slug}]] · статус <эмодзи> — продолжение восстанавливает это имя и цвет
   1. **Что продолжаем:** [[projects/<slug>/<slug>]] — <одна фраза о задаче>
   2. **Точки входа:** <файлы, с которых начинать>
   3. **Фон:** <что запущено, что помнить>
   4. **Ближайший шаг:** <одна строка>
   ```

   **Строка 1 обязана называть проект**, а не только задачу: после перезапуска чата фраза вроде
   «продолжаем второй этап» адресата не даёт — проект приходится искать поиском по репозиторию.
   Строка 0 держит идентичность: продолжение пишет в **тот же** атом, а не заводит новый.

2. Покажи владельцу в чате **короткий промпт на 2–5 строк** — сжатие этой секции. Первая строка
   начинается с проекта.

## MID-6. Мост между чатами (по просьбе)

По умолчанию хватает атома. Если владелец просит мост («сохрани для нового чата»), запиши
`.exocortex/memory/<агент>/session-handoff-{session_id}.md`: идентичность сессии + проект +
2–3 итога + 1–3 шага + ссылка на атом. Имя файла уникально на сессию — чужой мост перезаписать
невозможно. Мост **не заменяет** атом.

## MID-7. Атома нет (retrofit)

Сессия шла без атома — создай его сейчас из шаблона `operation/sessions/README.md`, перенеси
накопленное в «TL;DR» и «Хронология» с пометкой, что атом создан задним числом, и продолжай по
MID-3.

## MID-8. Порядок записи

Покажи черновик: (а) решения, (б) правки атома, (в) строка в день. После «да»: атом → день →
показать промпт на продолжение.
