# `.exocortex/memory/` — мост между чатами

Здесь живёт **мост сессии (handoff)**: сжатая записка, по которой работа возобновляется в новом
чате после `/clear`, перезапуска редактора или обрыва связи.

```
.exocortex/memory/<агент>/session-handoff-{session_id}.md
```

`<агент>` — среда, в которой шла работа (`claude-code`, `cowork`, `codex`).

## Правила

- **Файл уникален на сессию.** Имя строится из `session_id` атома — перезаписать чужой мост
  невозможно, а свежий находится сортировкой по имени.
- **Ротации нет.** Файл рождается датированным и становится архивом сам собой; реестра мостов не
  ведётся — обзор слоя делается просмотром папки.
- **Мост не заменяет атом.** Канонический итог сессии — `operation/sessions/S….md`; здесь только
  то, что нужно, чтобы продолжить: идентичность сессии, **проект**, 2–3 итога, 1–3 шага, ссылка на
  атом.
- Пишет фаза чекпоинта или итога навыка `session` — по просьбе владельца («сохрани для нового
  чата»), а не по умолчанию.

## Пример

```markdown
# Мост: S20260713T0930-first-concepts

0. **Сессия:** S20260713T0930-first-concepts · статус 🟡
1. **Проект:** [[projects/knowledge-base/knowledge-base]] — разбор материалов лекции в карточки
2. **Итоги:** три карточки в concepts/ · спорная терминология вынесена в discovery/
3. **Шаги:** дочитать блок 4 транскрипта → прогнать через /review-concepts
4. **Атом:** [[operation/sessions/S20260713T0930-first-concepts]]
```

> На ступени Team эта же зона становится **общим пулом** команды — но это про совместный доступ,
> а не про появление папки: личный мост живёт здесь с Base.
